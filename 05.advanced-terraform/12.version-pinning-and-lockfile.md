# Version pinning and the lockfile

At huge scale, "it worked on my laptop" usually means **different Terraform / provider / module versions**.

Pin all three.

### 1. Pin the Terraform CLI

```tf
terraform {
  required_version = ">= 1.8.0, < 2.0.0"
}
```

Also pin the **binary** in CI (not only the constraint):

- `.terraform-version` (tfenv / tenv)
- GitHub Action `hashicorp/setup-terraform` with `terraform_version: 1.10.5`

Everyone and CI must run the same CLI.

### 2. Pin providers

```tf
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.60"
    }
  }
}
```

- `~> 5.60` = `>= 5.60` and `< 6.0` (patches and minor, depending on the number of parts)
- Put this in **every root** and in **every child module** (compatibility). The root still wins the actual download.

Provider **major** bumps (AWS 5 → 6) are a project: read the upgrade guide, plan every root.

### 3. `.terraform.lock.hcl`

After `terraform init`, Terraform writes a lockfile with **exact provider versions and checksums**.

```bash
$ terraform init
# creates / updates .terraform.lock.hcl
```

**Commit `.terraform.lock.hcl` in every root module.**

- Teammates and CI get the same provider bits
- `terraform init` without `-upgrade` **reuses** the locked versions

```bash
# Everyday
$ terraform init

# Only when you INTEND to move providers
$ terraform init -upgrade
$ terraform plan
# then commit the new lockfile
```

>[!NOTE]
>
> The lockfile is for **providers** (and some other deps). **Module versions** are **not** stored there. You pin modules with `ref=` or registry `version =` (next lesson).

### 4. Pin modules

```tf
# Git tag (recommended)
source = "git::https://github.com/org/terraform-aws-vpc.git?ref=v1.2.0"

# Registry
source  = "app.terraform.io/your-org/vpc/aws"
version = "~> 1.2"
```

Never:

```tf
source = "git::https://github.com/org/terraform-aws-vpc.git?ref=main"
```

`main` moves. Yesterday's apply is not today's plan.

### 5. Upgrade workflow (boring on purpose)

1. One PR: `terraform init -upgrade` in **one** root (or bump one module `ref`)
2. `terraform plan` — read destroys
3. Merge and apply
4. Repeat for the next root / next module

Do not upgrade Terraform CLI, AWS provider, and 4 modules in the same Friday PR.

### 6. What to commit

| Commit | Do not commit |
|---|---|
| `.terraform.lock.hcl` (roots) | `.terraform/` directory |
| `required_version` / `required_providers` | Downloaded modules cache |

`.gitignore` should already ignore `.terraform/` and `*.tfstate`.
