# Stable addresses: count vs for_each

You learned `count`, `for_each`, and `dynamic` in `01.hashicorp-configuration-language`.

At huge scale the important question is: **what is the address in state after I add or delete one item?**

### 1. Why addresses must be stable

```text
count     →  aws_subnet.this[0]   aws_subnet.this[1]
for_each  →  aws_subnet.this["web"]   aws_subnet.this["data"]
```

If you **insert** a CIDR at the start of a list used by `count`, every index shifts. Terraform **destroys and recreates** almost everything.

If you **remove** `"web"` from a map used by `for_each`, only `aws_subnet.this["web"]` is destroyed.

### 2. Prefer `for_each` over a map keyed by name

```tf
variable "subnets" {
  type = map(object({
    cidr   = string
    az     = string
    public = optional(bool, false)
  }))
}

# terraform.tfvars
# subnets = {
#   web  = { cidr = "10.0.1.0/24", az = "us-east-1a", public = true }
#   data = { cidr = "10.0.2.0/24", az = "us-east-1b", public = false }
# }

resource "aws_subnet" "this" {
  for_each          = var.subnets
  vpc_id            = aws_vpc.this.id
  cidr_block        = each.value.cidr
  availability_zone = each.value.az

  tags = {
    Name = each.key
  }
}

output "subnet_ids" {
  value = { for k, s in aws_subnet.this : k => s.id }
}
```

Add `jobs` to the map → only one new subnet. Existing addresses stay.

### 3. When `count` is still correct

- **0 or 1** resource (`var.enabled`)
- A list that **never reorders** (rare — do not bet on this)

```tf
resource "aws_eip" "nat" {
  count  = var.enable_nat ? 1 : 0
  domain = "vpc"
}
```

```tf
# BAD for a growing list — inserting at index 0 recreates all
resource "aws_subnet" "this" {
  count      = length(var.subnet_cidrs)
  cidr_block = var.subnet_cidrs[count.index]
}
```

### 4. `for` expressions (transform, do not create)

```tf
locals {
  public_subnet_ids = [
    for k, s in aws_subnet.this : s.id if var.subnets[k].public
  ]

  subnet_cidrs = { for k, s in var.subnets : k => s.cidr }
}
```

Use `for` in `locals` and outputs. Use `for_each` / `count` on `resource` / `module`.

### 5. `dynamic` nested blocks (recap)

Use when the **nested block** really varies (SG rules, inline policies). Do not wrap every argument in `dynamic`.

```tf
dynamic "ingress" {
  for_each = var.ingress_ports
  content {
    from_port   = ingress.value
    to_port     = ingress.value
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
}
```

### 6. Modules and `for_each`

```tf
module "app" {
  for_each = var.apps
  source   = "git::https://github.com/org/terraform-aws-web.git?ref=v1.4.2"

  name   = each.key
  vpc_id = var.vpc_id
  image  = each.value.image
}
```

Addresses become `module.app["checkout"]`, `module.app["billing"]`. Removing `billing` from the map destroys only that module instance.

>[!NOTE]
>
> Convert `count` → `for_each` with a `moved` block per instance, or Terraform will recreate.
>
> ```tf
> moved {
>   from = aws_subnet.this[0]
>   to   = aws_subnet.this["web"]
> }
> ```
