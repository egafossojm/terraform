# HCP Terraform

HCP Terraform (formerly Terraform Cloud) stores state, locks it, and can run `plan` / `apply` for you. It is the managed alternative to an S3 backend.

Free organizations exist for small teams. Terraform Enterprise is the self-hosted product.

## Connect a root

`cloud` and `backend` cannot both be set.

```hcl
terraform {
  cloud {
    organization = "your-org"
    workspaces {
      name = "prod-network"
    }
  }
}
```

```bash
terraform login     # writes ~/.terraform.d/credentials.tfrc.json
terraform init
```

The workspace is created on init if it does not exist. One HCP workspace is one state. That is a different idea from `terraform workspace` (see `04.advanced-terraform/07.workspaces-when-and-when-not.md`).

| Execution mode | Where plan/apply run |
|---|---|
| Remote (default) | HCP Terraform agents. Cloud credentials live on the workspace. |
| Local | Your laptop or CI. State still lives in HCP Terraform. |

## Cloud credentials

Prefer OIDC over static access keys.

1. In AWS, create an IAM OIDC provider for `https://app.terraform.io` with audience `aws.workload.identity`.
2. Create a role whose trust policy allows `sts:AssumeRoleWithWebIdentity` for that provider, with `app.terraform.io:aud` = `aws.workload.identity` and `app.terraform.io:sub` matching your org, project, and workspace.
3. On the workspace, set environment variables: `TFC_AWS_PROVIDER_AUTH=true` and `TFC_AWS_RUN_ROLE_ARN=arn:aws:iam::ACCOUNT:role/terraform`.

The `sub` claim looks like:

```text
organization:ORG:project:PROJECT:workspace:WORKSPACE:run_phase:*
```

`Default Project` is the project name until you create one.

Workspace variables (Terraform variables or environment variables) are the HCP equivalent of tfvars and `TF_VAR_`. Mark secret ones sensitive. They still outrank `terraform.tfvars`.

## When to pick it

| Choose HCP Terraform | Choose S3 + CI |
|---|---|
| You want hosted runs, RBAC, policy (Sentinel), and state history in one product | You already run GitHub Actions or GitLab and want to own the pipeline |
| Many people apply and you want a single lock and audit trail | Cost or data-residency rules keep state in your account |

The plan-on-PR flow is the same idea either way: `04.advanced-terraform/16.ci-cd-and-gitops.md`.
