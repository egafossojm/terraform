# Remote state

Terraform is stateful. A local `terraform.tfstate` is fine for a solo lab. Shared work needs a remote backend so the state has a lock, encryption, and an access list.

## What a backend fixes

| Risk with a local file | Remote backend |
|---|---|
| Two applies at once corrupt state | Lock: the second run waits or fails |
| The file holds secrets in plaintext on a laptop | Encryption at rest, IAM on the bucket |
| No history after a bad apply | Bucket versioning, or HCP Terraform state versions |

The backend also decides where `plan` and `apply` run. The `s3` backend runs locally and stores state in S3. The `cloud` block runs (by default) in HCP Terraform.

## S3 backend (current)

Create the bucket first: versioning, SSE, Block Public Access, and a bucket policy limited to the Terraform roles. Then:

```hcl
terraform {
  backend "s3" {
    bucket       = "org-tfstate-prod"
    key          = "prod/network/terraform.tfstate"
    region       = "ca-central-1"
    encrypt      = true
    use_lockfile = true
    kms_key_id   = "arn:aws:kms:ca-central-1:123456789012:key/example"
  }
}
```

`use_lockfile = true` locks with an object in the same bucket (S3 conditional writes). One key per root module.

`dynamodb_table` is the legacy lock. You will still see it in older repos. New backends use `use_lockfile`.

```bash
terraform init            # first time, or after a backend edit
terraform init -migrate-state    # copy an existing state into the new backend
terraform init -reconfigure      # switch backends and drop the previous local config
```

## Partial configuration

Backend blocks cannot use `var` or `local`. When many roots share a bucket, commit the key in each root, or pass the rest at init:

```bash
terraform init -backend-config=backend.hcl
```

Changing the backend is a migration, not an edit you discover at apply time. Run `init -migrate-state` once and confirm `terraform state list` before the next apply.

## Bootstrap

The state bucket cannot live in the state it stores. A tiny `_bootstrap` root (or a one-time console step) creates the bucket. Apply that root rarely.
