# Loops in Terraform
- By default, a terraform resource block configer `one (01)` infrastructure object. 
- However,  sometimes you want to several similar objects `without writing a separate resource block` for each one.
- In terraform there are two ways to do this : **count** or **for_each**.

### 1. `count` meta-argument
`count` is used to manage similar resources.

EX1: create 3 ec2 instances
```tf
resource "aws_instance" "my_vm" {
  ami                         = data.aws_ami.amazon_linux_2023.image_id
  instance_type               = var.instance_params[0]
  vpc_security_group_ids      = [aws_default_security_group.default_sg.id]
  associate_public_ip_address = var.instance_params[2]
  key_name                    = aws_key_pair.test_ssh_key.key_name
  subnet_id                   = aws_subnet.web.id
  count                       = 3
  user_data                   = file("entry-script.sh")

  tags = {
    "Name" = "${var.main_vpc_name} VM"
  }
}

output "public_ips" { 
  value       = aws_instance.my_vm[*].public_ip # if count used
  description = "Public IP of the instances"
}

output "vpc1_id" {
  value       = aws_vpc.vpc1.id
  description = "VPC1 ID"
}

output "ami_ids" { # If count used
  value       = aws_instance.my_vm[*].ami
  description = "Instace AMI ID of instances"
  sensitive   = false
}
```

- run

```bash
$ terraform apply -auto-approve

Outputs:

  "ami-0e935daee3c98f0ce",
  "ami-0e935daee3c98f0ce",
  "ami-0e935daee3c98f0ce",
]

  "16.52.158.137",
  "16.52.78.15",
  "35.182.53.234",
]

```

- view created resources


EX2: Create 5 AMI users

```tf
variable "iam_users" {
  type = list(string)
  default = [ 
    "demo-user",
    "dev-user",
    "ops-user",
    "sec-user"
    ]
}


resource "aws_iam_user" "users" {
  count = length(var.iam_users)
  name = var.iam_users[count.index]
  path = "/systems/"
}
```

>[NOTE]
>
> The problem with `count`:
> - If you delete an element in the middle of the list, ALL remaining elements will be affected.
> - This is because count work with the order of elements in the list.
> - Running `terraform apply` will fail, since terraform will create a resource that already exist (In a different index).
> - You need to destroy everything and recreate again.
> - `for_each` will solve this problem.




### 2. `for_each` meta-argument
- Use `for_each` meta-argument with **set** and **map** types, since they do not allow duplicate items.
- there is no order of the resources for each element.
- changing the list will not affect remaining elements

EX:
```tf
variable "iam_users" {
  type = list(string)
  default = [ 
    "demo-user",
    "dev-user",
    "ops-user",
    "sec-user"
    ]
}

resource "aws_iam_user" "users" { 
  for_each = toset(var.iam_users)
  name = each.key
  path = "/systems/"
}
```

- You can delete **dev-user** from the list and run `terraform apply` with no issue.

### 3. `dynamic` nested block
EX:
```tf
variable "ingress_ports" {
  description = "List of Ingress Ports"
  type = list(number)
  default = [ 22, 80, 8080, 443 ]
}

resource "aws_default_security_group" "default_sg" {
  vpc_id = aws_vpc.vpc1.id

  dynamic "ingress" {
    for_each = var.ingress_ports
    content {
      from_port = ingress.value
      to_port = ingress.value
      protocol = "tcp"
      cidr_blocks = ["0.0.0.0/0"]
    } 
  }

  egress {
    from_port   = var.egress_default_sp_params["from_port"]
    to_port     = var.egress_default_sp_params["to_port"]
    protocol    = var.egress_default_sp_params["protocol"]
    cidr_blocks = var.egress_default_sp_params["cidr"]
  }

  tags = {
    "Name" = "${var.main_vpc_name} Default SG"
  }
}
```
- The name of the dynamic block(**"ingress"**), specify what kind of nested block to generate inside the resource block.
- You can generate nested blocks inside :  `resource`, `data`, `provider` and `provisioner`.
the `for_each` argument provides the collection variable to iterate over(list, tuple, set, map, object)
- The nested `content` block defines the body of each generated ingress block.
- To access an element of the list in the current iteration, use the **name of the dynamic block** ("ingress"in this case) dot "value" for a list: `ingress.value` or dot "key" for a map: `ingress.key`
