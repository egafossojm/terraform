# Performance and day-2 operations

Day-2 = everything after the first successful apply: upgrades, imports, incidents, rollback.

### 1. Make plans fast

Biggest win: **split state** (lesson `03`). A 20 minute plan is usually "too many resources in one state".

Other levers:

```bash
$ terraform apply -parallelism=20   # default is 10; watch API rate limits
```

- Avoid `data "aws_instances" "all"` and other "list the whole account" data sources
- Filter data sources (tags, ids)
- Do not put thousands of objects in one `for_each` if another stack can own them
- `-refresh=false` skips talking to the cloud. **Faster and dangerous** (hides drift). Rare hotfix only.

```bash
$ terraform plan -refresh=false
```

Upgrade the Terraform CLI when you can — graph evaluation got faster in recent versions.

### 2. `-target` again

Use only to **unblock**. Then run a full plan. See lesson `09`.

### 3. Import existing clouds in slices

Do not boil the ocean.

1. Pick one stack (e.g. "prod DNS zone")
2. Write the `resource` blocks (or `generate-config`)
3. `import` block / `terraform import`
4. `plan` until only intended diffs remain
5. Next slice

### 4. Refactor without recreate

- Rename → `moved` (lesson `05`)
- Move into a module → `moved`
- Stop managing, keep the object → `removed` / `state rm`
- Adopt click-ops → `import`

### 5. Rollback (Terraform has no undo)

`git revert` + apply **previous configuration** is the usual rollback.

That is **not** the same as:

- Restoring an old **state** file (can make Terraform try to recreate things that still exist, or forget things you created after)
- Undoing an RDS `apply` that already deleted a database (you need a **backup restore**, not Git)

Rules:

- S3 / TFC **state versioning** is break-glass, not everyday undo
- `prevent_destroy` on irreplaceable resources
- Read the plan **destroy** count every time

### 6. Destroy

```bash
$ terraform destroy
```

Almost **never** on a prod root. Use destroy on:

- Throwaway PR environments
- Labs
- A dedicated teardown workspace

For one object, remove it from code (or `count = 0`) and apply — still read the plan.

### 7. Upgrade cadence

| What | How often (example) |
|---|---|
| Terraform CLI | Quarterly, pin in CI |
| Providers | Monthly lockfile PRs (`init -upgrade`) |
| Modules | When you need the feature; promote env by env |

Never combine a CLI major, a provider major, and a module major in one night.

### 8. Break-glass

Document (in the live README):

- Who can `state pull` / unlock a stuck lock
- How to remove a stale S3 lock file
- How to import after a panic console fix
- How to restore state from bucket versioning

```bash
# example: someone cancelled apply, lock remains (backend-specific)
$ terraform force-unlock LOCK_ID
```

>[!WARNING]
>
> `force-unlock` only when you are **sure** no other apply is running. Unlocking a live apply can corrupt state.
