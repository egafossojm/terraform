# Multi-account and provider aliases

Huge orgs use **several AWS accounts** and **several regions**. One `provider "aws"` is not enough.

### 1. Default provider + alias

```tf
provider "aws" {
  region = "eu-west-1"
}

provider "aws" {
  alias  = "dns"
  region = "us-east-1"
}

resource "aws_route53_zone" "public" {
  provider = aws.dns
  name     = "example.com"
}
```

- No `alias` → this is the **default** provider (used when you omit `provider`).
- `alias = "dns"` → you must set `provider = aws.dns` on the resource (or pass it into a module).

### 2. Assume a role (one identity, many accounts)

CI (or you) authenticates to a **tools** account, then assumes a role in `dev` / `prod`.

```tf
provider "aws" {
  alias  = "prod"
  region = "eu-west-1"

  assume_role {
    role_arn     = "arn:aws:iam::222233334444:role/terraform-apply"
    session_name = "terraform-prod"
  }
}

provider "aws" {
  alias  = "dev"
  region = "eu-west-1"

  assume_role {
    role_arn     = "arn:aws:iam::111122223333:role/terraform-apply"
    session_name = "terraform-dev"
  }
}
```

Prefer **OIDC** from GitHub Actions (or similar) over long-lived access keys. See lesson `16`.

### 3. Pass aliases into a module

The child module still says `provider "aws"` (no alias) **or** declares a `configuration_aliases` requirement. The root **maps** the alias:

```tf
# root
module "acm_for_cloudfront" {
  source = "./modules/acm"

  providers = {
    aws = aws.dns
  }

  domain_name = "www.example.com"
}
```

Inside the module, resources use the default `aws` provider. That default **is** `aws.dns` for this module instance.

>[!NOTE]
>
> If a module needs **two** AWS providers (app region + us-east-1 for ACM):
>
> ```tf
> terraform {
>   required_providers {
>     aws = {
>       source                = "hashicorp/aws"
>       configuration_aliases = [aws, aws.dns]
>     }
>   }
> }
> ```

### 4. `default_tags` (do this on every provider)

```tf
provider "aws" {
  region = var.aws_region

  default_tags {
    tags = {
      ManagedBy   = "terraform"
      Environment = var.environment
      Stack       = "prod/app"
      Owner       = "payments"
    }
  }
}
```

Every resource gets these tags unless it overrides them. This is how you find cost and owners later.

### 5. Practical layout for huge org

```text
accounts:
  security          — SCPs, GuardDuty (very few people apply)
  shared-services   — DNS, AMIs, state bucket
  dev / staging / prod
```

- One **live root** per account (or per account + region + product).
- One provider alias per **account + region** pair if a single root must talk to two accounts (try to avoid that).
- Prefer **data sources** / SSM across accounts over one root that applies to five accounts.

### 6. Other clouds

The same idea exists for `azurerm`, `google`, `kubernetes`:

```tf
provider "kubernetes" {
  alias                  = "prod_cluster"
  host                   = module.eks.endpoint
  cluster_ca_certificate = base64decode(module.eks.ca)
  token                  = data.aws_eks_cluster_auth.prod.token
}
```

Create the cluster in one root. Configure the Kubernetes provider in a **later** root (or a second apply) so you do not fight chicken-and-egg in the same state.
