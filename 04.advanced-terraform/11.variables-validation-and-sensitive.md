# Variables: types, validation, sensitive

Chapter `00` introduced variables. For huge infra, the variable block **is the module API**. Make it strict.

### 1. Objects and `optional()`

Prefer a **map of objects** over five parallel lists.

```tf
variable "subnets" {
  type = map(object({
    cidr   = string
    az     = string
    public = optional(bool, false)
  }))

  validation {
    condition = alltrue([
      for s in var.subnets : can(cidrhost(s.cidr, 0))
    ])
    error_message = "Each subnet.cidr must be a valid CIDR."
  }
}
```

- `optional(bool, false)` lets you add a field later **without** breaking old callers.
- `nullable = false` when `null` would be dangerous.

```tf
variable "name" {
  type     = string
  nullable = false
}
```

### 2. Validation

```tf
variable "environment" {
  type = string

  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "environment must be dev, staging, or prod."
  }
}
```

Fail at `plan`, before the provider returns an error. Since Terraform 1.9 a `validation` block may reference other variables.

### 3. Variable precedence (high → low)

1. `-var` and `-var-file` on the CLI (later flags win), and HCP Terraform variables
2. `*.auto.tfvars` / `*.auto.tfvars.json` (lexical filename order)
3. `terraform.tfvars.json`
4. `terraform.tfvars`
5. `TF_VAR_name` environment variables
6. Variable `default`

```bash
$ terraform apply -var-file="prod.tfvars" -var="instance_type=t3.large"
$ export TF_VAR_vpc_id=vpc-0aa11aa98e9111f53
```

>[!NOTE]
>
> A missing tfvars file leaves the `default` in place. `terraform.tfvars` and `*.auto.tfvars` outrank `TF_VAR_*`. CLI flags outrank both.

### 4. `sensitive` — hides from CLI, **not** from state

```tf
variable "db_password" {
  type      = string
  sensitive = true
}

output "db_password" {
  value     = var.db_password
  sensitive = true
}
```

`terraform output` will hide it. **State still stores it in JSON.**

You already saw this risk in `09.terraform-state.md` and `03` secrets.

Rules:

- Encrypt remote state
- Restrict who can `state pull`
- Prefer an ephemeral read (Terraform 1.10+) passed to a write-only argument such as `password_wo` (Terraform 1.11+). A normal data source still stores the secret in state. See [`02/03`](../02.secrets-and-remote-state/03.working-with-secrets.md).

### 5. What belongs in tfvars vs Git

| Commit in Git | Inject at apply (CI / secret store) |
|---|---|
| CIDRs, instance types, names | DB passwords, API tokens |
| Non-secret tfvars per env | Anything that could leak in a PR |

Never commit `secrets.tfvars` or `.env` with real credentials.

### 6. Locals vs variables (recap)

From chapter `01`:

- **Variable** = input the user/CI must set
- **Local** = computed inside the module (`merge` tags, build a name)

```tf
locals {
  name_prefix = "${var.environment}-${var.name}"
  common_tags = merge(var.tags, {
    Environment = var.environment
    ManagedBy   = "terraform"
  })
}
```
