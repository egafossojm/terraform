# Orchestrators: Terragrunt, Terramate, Atmos

When you have **many** roots, the thin files repeat:

- `backend.tf` (only the `key` changes)
- `versions.tf`
- `providers.tf`
- `terraform.tfvars` that mostly differ by account id

An **orchestrator** generates that boilerplate and runs stacks in dependency order.

It does **not** replace modules. Modules stay in Git with `ref=` / a registry.

### 1. When you do **not** need one

- A handful of roots (`dev/app`, `prod/app`, `prod/network`)
- Copy-paste of a 15-line `backend` block is acceptable (lesson `02`: DRY modules, not roots)

Start with **directories**. Add an orchestrator when the pain is real.

### 2. Terragrunt (most common)

Terragrunt is a thin wrapper around Terraform.

Typical layout:

```text
live/
  terragrunt.hcl              # remote state + providers generated
  prod/
    env.hcl                   # account, region
    network/
      terragrunt.hcl
    app/
      terragrunt.hcl
  dev/
    env.hcl
    network/
    app/
```

`live/prod/app/terragrunt.hcl` idea:

```hcl
include "root" {
  path = find_in_parent_folders("terragrunt.hcl")
}

dependency "network" {
  config_path = "../network"
}

terraform {
  source = "git::https://github.com/org/terraform-aws-web.git?ref=v1.4.2"
}

inputs = {
  vpc_id = dependency.network.outputs.vpc_id
  name   = "checkout"
}
```

```bash
$ terragrunt plan
$ terragrunt run-all plan    # walks the graph
$ terragrunt run-all apply
```

Benefits:

- One place to define the S3 backend pattern
- `dependency` replaces a lot of hand-written `terraform_remote_state`
- `run-all` applies `network` before `app`

Costs:

- Another tool to learn
- YAML/HCL wrapper errors on top of Terraform errors
- Team must install Terragrunt in CI

### 3. Other names you will see

| Tool | Idea |
|---|---|
| **Terramate** | Generate stacks + change detection (which stacks a PR affects) |
| **Atmos** (Cloud Posse) | Stacks + components + catalogs, YAML-heavy |
| **Terragrunt** | Keep Terraform, DRY the roots |
| **TFC / Spacelift stack graph** | Same problem, hosted |

Pick **one**. Do not run Terragrunt **and** Atmos **and** custom bash.

### 4. What still stays in Terraform

- Resource graph
- State
- Modules
- `moved` / `import`
- Providers

The orchestrator only:

- Fills backend / provider boilerplate
- Injects `inputs`
- Orders `plan` / `apply` across roots

### 5. Rule

```text
Need reuse of RESOURCES     → Terraform modules
Need reuse of ROOT FILES    → orchestrator (or accept copy-paste)
Need reuse of RUNS / RBAC   → TFC / Atlantis / Spacelift
```
