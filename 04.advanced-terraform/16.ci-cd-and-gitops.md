# CI/CD and GitOps

The safest huge-infra rule: **humans open PRs, CI plans, merge applies**. Laptops do not apply to prod.

### 1. Minimum pipeline

1. `terraform fmt -check`
2. `terraform validate`
3. `tflint` / `trivy` / `checkov` (policy)
4. **`plan` on the PR** (comment or artifact)
5. **`apply` on merge to `main`** for **that root only**
6. Save the plan / apply logs

```bash
$ terraform fmt -check -recursive
$ terraform init -input=false
$ terraform validate
$ terraform plan -input=false -out=tfplan
# after merge, same commit:
$ terraform apply -input=false tfplan
```

Apply the **exact** reviewed plan when you can (Terraform Cloud / Spacelift / Atlantis do this natively).

### 2. Path filters (do not plan the world)

If the PR only touches `live/prod/apps/checkout`, CI should init/plan **that** directory.

Also plan consumers when a **shared module** in a monorepo changes (`modules/vpc` → plan every live stack that calls it).

### 3. Identity: OIDC, not static keys

GitHub Actions (or GitLab) assumes an AWS role. No long-lived `AWS_ACCESS_KEY_ID` in secrets if you can avoid it.

Ideas:

- **Plan role**: read-only / no IAM create (or a dedicated plan role)
- **Apply role**: stronger, only on `main`
- One role per account (`dev` vs `prod`)

Concurrency: **one apply per state key** (backend lock + CI group `prod-network`).

### 4. GitOps mapping

```text
PR opened     → terraform plan   (speculative)
PR approved   → humans read destroys
PR merged     → terraform apply  (same SHA)
```

- `main` is the desired state of **live**
- Drift (console click) is an incident: scheduled `plan` should show it

### 5. Tools that wrap this

| Tool | Role |
|---|---|
| GitHub Actions / GitLab CI | You wire the steps |
| Atlantis | Comments `plan` / `apply` on the PR |
| HCP Terraform / TFC | Remote runs, state, RBAC, policy |
| Spacelift / Env0 | Same idea, extra stack graph |

Worth it when you have many roots and many authors.

### 6. Drift

```bash
# scheduled nightly on each prod root
$ terraform plan -detailed-exitcode
# exit 0 = no change, 2 = changes, 1 = error
```

- Drift = someone clicked the console, a provider bug, or a leaked apply
- Do **not** re-apply blindly if the plan surprises you
- Prefer "import or revert" over "apply to make the warning go away"

### 7. What CI must be allowed to do

- Clone **private module** repos (`ref=` Git sources)
- Assume the cloud role
- Read/write **that** state key (apply) or read (plan)
- Not: delete the state bucket, not: apply a different env's state

>[!WARNING]
>
> Never print `terraform output -json` of a stack full of secrets into a public PR comment. Mark outputs `sensitive` and keep plan comments in a private repo.
