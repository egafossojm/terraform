# Input variables

Variables are the arguments of a module. They are fixed for the whole run. Callers set them before `plan`.

```hcl
variable "vpc_cidr_block" {
  type        = string
  description = "CIDR for the VPC"
  default     = "10.0.0.0/16"
}

resource "aws_vpc" "main" {
  cidr_block = var.vpc_cidr_block
  tags       = { Name = "Production ${var.vpc_name}" }
}
```

Declare them in `variables.tf`. A variable with no `default` is required: `plan` errors (or prompts, if a terminal is attached) until a value arrives.

`type = string` is an expression, not a quoted string. Quoted `"string"` is a legacy form.

## Where values come from

| Source | Loaded automatically? |
|---|---|
| `default` on the variable | Yes |
| `TF_VAR_<name>` in the environment | Yes |
| `terraform.tfvars` | Yes |
| `terraform.tfvars.json` | Yes |
| `*.auto.tfvars` and `*.auto.tfvars.json` | Yes, lexical filename order |
| `-var` and `-var-file` | Only when you pass them |
| HCP Terraform workspace variables | On remote runs |

```bash
export TF_VAR_vpc_cidr_block="10.1.0.0/16"
terraform plan -var="vpc_cidr_block=10.2.0.0/16" -var-file=prod.tfvars
```

Any other filename (`dev.tfvars`) needs `-var-file`.

## Precedence (highest wins)

1. `-var`, `-var-file`, and HCP Terraform variables
2. `*.auto.tfvars` / `*.auto.tfvars.json` (lexical order)
3. `terraform.tfvars.json`
4. `terraform.tfvars`
5. `TF_VAR_*`
6. `default`

Child modules do not read `terraform.tfvars`. The parent passes arguments:

```hcl
module "vpc" {
  source         = "../modules/vpc"
  vpc_cidr_block = var.vpc_cidr_block
}
```
