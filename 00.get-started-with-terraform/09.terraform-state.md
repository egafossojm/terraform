# State

State maps config addresses to real objects and caches their attributes. The default file is `terraform.tfstate`, created on the first `apply`. A local run also writes `terraform.tfstate.backup`.

On each plan Terraform refreshes state from the provider, diffs it against config, then (on apply) updates the cloud and the state.

## What is inside

JSON. Important fields: `terraform_version`, `serial`, `lineage`, `outputs`, `resources`.

Each resource entry has `mode` (`managed` or `data`), `type`, `name`, `provider`, and `instances` (attributes, dependencies, index or `for_each` key).

State is plaintext. It holds IDs and often passwords, keys, and tokens. Remote state with encryption and tight IAM is the production default. See [`02`](../02.secrets-and-remote-state/README.md).

## Inspect it

| Command | Use |
|---|---|
| `terraform state list` | Addresses only |
| `terraform state show aws_vpc.main` | One object |
| `terraform show` | Human-readable state or a saved plan |
| `terraform show -json` | Machine-readable |

```text
aws_instance.web
aws_instance.web[0]          # count
aws_instance.web["api"]      # for_each
module.vpc.aws_vpc.main
```

Renaming an address in code without telling state plans a destroy plus a create. Record the rename with a `moved` block: [`04/05`](../04.advanced-terraform/05.state-refactoring-moved-import.md).

Edit state through `terraform state` subcommands or `moved` / `import` / `removed` blocks. Hand-editing the JSON drops `serial` and `lineage` discipline and races with locking.

> [!TIP]
> Treat the state file like a database of your infrastructure, including its secrets. Restrict who can read it the same way you restrict production credentials.
