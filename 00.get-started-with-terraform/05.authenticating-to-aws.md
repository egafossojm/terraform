# Authenticating to AWS

The AWS provider walks a credential chain. The first match wins.

| Order | Source | When |
|---|---|---|
| 1 | `access_key` / `secret_key` in the `provider` block | Almost never. A key in Git is a leak. |
| 2 | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` | Short-lived local experiments |
| 3 | Shared config: `~/.aws/credentials` and `~/.aws/config` (`AWS_PROFILE`) | Laptop. Prefer IAM Identity Center or `aws login`. |
| 4 | ECS / EKS task role | Terraform running in a container |
| 5 | EC2 instance profile (IMDSv2) | Terraform running on an instance |

```hcl
provider "aws" {
  region = "ca-central-1"
  # no keys here
}
```

```bash
export AWS_PROFILE=dev
export AWS_REGION=ca-central-1
aws sts get-caller-identity   # confirm who Terraform will be
terraform plan
```

## What to use where

| Place | Identity |
|---|---|
| Laptop | Named profile, SSO, or `aws login`. Short sessions. |
| CI | OIDC: the pipeline assumes an IAM role. No long-lived access keys. |
| Instance or task | The instance profile or task role. |

Assume-role and provider aliases: [`04/10`](../04.advanced-terraform/10.multi-account-and-provider-aliases.md). CI with OIDC: [`04/16`](../04.advanced-terraform/16.ci-cd-and-gitops.md).

> [!TIP]
> If a plan touches the wrong account, check `AWS_PROFILE` and `terraform workspace show` before you read the diff.
