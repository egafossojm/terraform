# Workflow

Terraform compares three things: **configuration**, **state**, and the **real API**. `plan` is the diff. `apply` performs it and writes state.

```text
.tf + variables  →  state  →  provider reads  →  plan  →  apply  →  new state
```

## Commands you use every day

| Command | What it does |
|---|---|
| `terraform init` | Install providers and modules, configure the backend. Safe to re-run. |
| `terraform fmt -recursive` | Rewrite HCL to the canonical style. |
| `terraform validate` | Check syntax and argument names. Needs `init` first. |
| `terraform plan` | Show the diff. Changes nothing. |
| `terraform plan -out=tfplan` | Save a binary plan. |
| `terraform apply tfplan` | Apply that exact plan. |
| `terraform apply -auto-approve` | Apply with no prompt. Normal in CI, risky on a laptop. |
| `terraform destroy` | Destroy everything in this state. |
| `terraform output` | Print root outputs stored in state. |
| `terraform console` | Evaluate expressions against the current state. |

```bash
terraform fmt -recursive
terraform init
terraform validate
terraform plan -out=tfplan
terraform apply tfplan
```

`-chdir=dir` runs the command from another directory: `terraform -chdir=live/prod/network plan`.

## Replace, refresh, graph

| Command | What it does |
|---|---|
| `terraform apply -replace='aws_instance.web'` | Destroy and recreate that address. Replaces the old `taint`. |
| `terraform plan -refresh-only` | Update state from the cloud, change no infrastructure. |
| `terraform graph` | Print the dependency graph (Graphviz). |
| `terraform force-unlock LOCK_ID` | Clear a stuck lock. Only when no apply is running. |

`-target=aws_vpc.main` limits an apply to one address. Use it to unblock a broken apply, then run a full plan. A targeted apply can leave the rest of the state stale.

## Files `init` creates

| Path | Commit? | Role |
|---|---|---|
| `.terraform.lock.hcl` | Yes | Provider versions and checksums |
| `.terraform/` | No | Plugin and module cache |
| `terraform.tfstate` | No | State. Local only until you add a backend. |

`init -upgrade` is how you intentionally move provider versions. Commit the updated lock file in that same change.

Other subcommands (`state`, `import`, `workspace`, `test`) have their own notes later in this repo.
